# Go2Gether — веб-клиент

Веб-интерфейс платформы совместных спортивных активностей Go2Gether: лента и поиск мероприятий, создание мероприятий, свободная запись и заявки, обсуждения, организации и их допуск, кабинет организатора и админ-панель.

Backend — отдельный репозиторий [crazy-tosser3/StolotoSportBack](https://github.com/crazy-tosser3/StolotoSportBack). Его README описывает API, модель данных, базу, демо-данные, права доступа и проверку сценариев через Swagger. Здесь — всё, что относится к интерфейсу: как его запустить, как пройти шесть сценариев мышкой, где что лежит в коде и что реализовано не полностью. Правила бизнес-логики повторно не описываются — даются ссылки на разделы backend-README.

Документ описывает состояние ветки `main` на 20.10.2026 и backend-сборку от 20.10.2026 (миграции `V01`–`V18`).

## Быстрый старт

Для основных сценариев нужен работающий backend: интерфейс не хранит данные сам. Без backend его можно запустить на встроенных моках (см. [режимы работы](#режимы-работы-с-api)).

**Нужно:** Node.js 22.18+ или 24.12+ (в `.nvmrc` — 24), pnpm 12 (версия закреплена в `packageManager` в `package.json`), запущенный backend.

1. Запустить backend по его [быстрому старту](https://github.com/crazy-tosser3/StolotoSportBack#быстрый-старт). Он поднимется на `http://localhost:8080`.
2. Установить зависимости фронтенда:

   ```bash
   pnpm install
   ```

3. Создать локальные настройки:

   ```bash
   cp .env.example .env.local
   ```

   В `.env.local` поставить `VITE_API_MOCK=false`. Если backend на другом порту — поправить `API_PROXY_TARGET`.

4. Запустить dev-сервер:

   ```bash
   pnpm dev
   ```

   Интерфейс — <http://localhost:5173>. Dev-сервер проксирует `/api` на backend, поэтому CORS настраивать не нужно.

5. Открыть «Войти» → «Быстрый вход» и выбрать роль (см. [Демо-роли](#демо-роли-и-вход)).

**Сборка и предпросмотр:**

```bash
pnpm build
```

```bash
pnpm preview
```

`pnpm build` собирает статику в `dist/`. `pnpm preview` раздаёт её на <http://localhost:4173>, но без прокси `/api`: для работы с backend сборку нужно раздавать с того же домена, что и API (запросы идут на относительный путь `/api/v1`). Готовой конфигурации развёртывания в репозитории нет.

**Все команды** (`package.json`):

| Команда | Что делает |
|---|---|
| `pnpm dev` | dev-сервер на <http://localhost:5173> |
| `pnpm build` | production-сборка в `dist/` |
| `pnpm preview` | раздать `dist/` локально |
| `pnpm lint` | oxlint + ESLint |
| `pnpm typecheck` | проверка типов `vue-tsc` |
| `pnpm test` | unit- и компонентные тесты Vitest |
| `pnpm e2e` | браузерные тесты Playwright (на моках) |
| `pnpm format` | Prettier для `src/` |
| `pnpm api:types` | сгенерировать `src/api/schema.d.ts` из `openapi/backend.json` |

> Проверено 20.10.2026 на macOS, Node 24.21, pnpm 12.10: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm e2e` — без ошибок; `pnpm dev` с backend-сборкой от 20.10.2026 (jar, порт 8081, `API_PROXY_TARGET=http://localhost:8081`). `pnpm preview` не проверялся.

**Если не запускается:**

| Симптом | Причина и решение |
|---|---|
| «Не получилось загрузить демо-аккаунты», любые запросы — ошибка | Backend не запущен или `API_PROXY_TARGET` указывает не туда. Проверить `curl http://localhost:8080/api/v1/sports` |
| `Port 5173 is in use` | Порт занят — Vite выберет следующий свободный и напишет его в консоли |
| После входа сразу снова «Войти» в Safari или при заходе по IP | Backend ставит cookie с `Secure`. Dev-прокси снимает этот флаг (`vite.config.ts`), поэтому открывайте приложение через `pnpm dev`, а не напрямую на порт backend |
| После перезапуска backend на экране входа ошибка | В браузере осталась устаревшая cookie. Dev-прокси удаляет её на первый ответ `401`; если не помогло — обновить страницу |
| Вместо карты надпись «Карта не подключена в этой сборке» | Не задан `VITE_2GIS_KEY` — это нормально, всё остальное работает |
| `ERR_PNPM_BAD_PM_VERSION` | Другая версия pnpm: `corepack enable`, затем повторить `pnpm install` |

## Переменные окружения

Переменные читаются из `.env.local` (в git не попадает). Шаблон — [`.env.example`](.env.example). Всё, что начинается с `VITE_`, встраивается в браузерный бандл и **видно любому посетителю** — секретов там быть не должно.

| Переменная | Назначение | Обязательна | Пример безопасного значения |
|---|---|---|---|
| `VITE_API_MOCK` | `true` — запросы обслуживают моки в браузере (backend не нужен), `false` — запросы идут в backend | нет (в шаблоне `true`) | `false` |
| `API_PROXY_TARGET` | Куда dev-сервер проксирует `/api`. Читается только `vite.config.ts`, в бандл не попадает | нет | `http://localhost:8080` (по умолчанию) |
| `VITE_2GIS_KEY` | Публичный ключ 2ГИС для карты, геокодера и выбора точки на карте. В кабинете 2ГИС у ключа должны быть включены MapGL JS API, Map Tiles API и Geocoder API; ключ стоит ограничить доменом | нет — без ключа карта заменяется сообщением | пусто |
| `E2E_PORT` | Порт dev-сервера для `pnpm e2e`, если 5174 занят | нет | `5176` |

Адрес backend в коде не зашит: клиент ходит на относительный `/api/v1` (`src/api/http.ts`), а куда это уходит, решает прокси `vite.config.ts` в разработке или веб-сервер в production.

### Режимы работы с API

| Режим | Как включить | Что происходит |
|---|---|---|
| Реальный backend | `VITE_API_MOCK=false` | Все данные с сервера, вход через cookie `jwt`, которую ставит backend |
| Моки | `VITE_API_MOCK=true` | [Mock Service Worker](https://mswjs.io/) перехватывает запросы в браузере (`src/mocks/`). Данные — в памяти вкладки, перезагрузка страницы возвращает демо-данные и сбрасывает вход. Нужен для разработки без backend и для e2e |

Моки повторяют контракт и правила backend (числовые id, страницы с нуля, коды ошибок, видимость снятых мероприятий, жалобы), но **демо-люди и мероприятия в моках другие**, чем в базе backend: имена и названия ниже по тексту относятся к реальному backend.

## Демо-роли и вход

Кнопка «Войти» рядом с именем входит без пароля (демо-вход backend). Уже вошедший пользователь меняет роль через меню аватара → «Сменить роль». Обычный вход по почте и паролю — форма «или по почте» на той же странице (пароль демо-аккаунтов `Demo1234!`).

| Аккаунт | Роль | Что проверять |
|---|---|---|
| Алексей Петров, `user@demo.local` | пользователь | С1, С4 (организатор тенниса), С5 (организатор баскетбола 3×3 на набережной) |
| Мария Иванова, `user2@demo.local` | пользователь | С3, С4 (участница), С5 (вопрос), С6 (участница пробежки) |

| Елена Козлова, `org2@demo.local` | представитель организаций на рассмотрении и отклонённой | С2 (ожидание и отказ) |
| Администратор, `admin@demo.local` | администратор | С2 (допуск), С6 (снятие), жалобы |

Что видит каждая роль:

| Роль | Навигация | Доступно |
|---|---|---|
| Гость | Главная, Мероприятия, Организации | Лента, карточки (без точного адреса и карты), обсуждения на чтение, страницы организаций. Действия «Записаться», «Создать», вопрос в обсуждении ведут на вход |
| Пользователь | + «Мои записи», «+ Создать», меню аватара: профиль, мои мероприятия, моя организация | Запись и заявки, создание и редактирование своих мероприятий, заявки и участники, обсуждения, жалобы, подача организации |
| Представитель организации | как у пользователя | + публикация от имени допущенной организации (переключатель «От чьего имени» в форме), ответы в обсуждении от имени организации |

Права в интерфейсе — только удобство: кнопки скрываются, маршруты с `requiresAuth`/`adminOnly`/`noAdmin` перенаправляют (`src/router/access.ts`). Настоящая проверка прав — на backend ([Права доступа](https://github.com/crazy-tosser3/StolotoSportBack#права-доступа-и-модерация)).

## Шесть базовых сценариев

**Общие условия.** Backend запущен на чистой базе ([восстановление исходного состояния](https://github.com/crazy-tosser3/StolotoSportBack#восстановление-исходного-состояния)), фронтенд — по [быстрому старту](#быстрый-старт), `VITE_API_MOCK=false`. Демо-данные меняются по ходу проверки (заявки принимаются, мероприятия снимаются) — при повторном прохождении базу нужно сбросить или брать другие мероприятия. Номера мероприятий — из таблицы демо-данных backend; открыть мероприятие можно поиском в ленте или по адресу `/events/<id>`.

**Как проверялось.** Все шесть сценариев автоматически проходят в браузере на моках (`e2e/scenarios.spec.ts`, 20.10.2026). На реальном backend полный ручной проход сценариев через интерфейс выполнялся 19.10.2026 на предыдущей сборке; на сборке 20.10.2026 повторно проверены вход, лента, карточка, онбординг и профиль, жалобы, скрытие адреса для гостя и поведение заявки после отказа. Эндпоинты сценариев 1–6 между этими сборками не менялись.

### Сценарий 1. Создание мероприятия пользователем

**Цель:** пользователь публикует мероприятие, другой находит и открывает его.
**Роли:** Алексей Петров — автор; Мария Иванова — проверяет. **Начальные условия:** нет.

1. Войти как Алексей. Нажать «+ Создать» в шапке (на телефоне — круглая «+» в нижней панели). Откроется `/events/new` «Новое мероприятие».
2. Блок «Что и когда»: «Название», «Направление», «Дата», «Начало», при желании «Окончание» и «Описание».
   - «Направление» — поле с подсказками: начните вводить, выберите вариант из списка.
3. Блок «Где»: «Город», «Адрес» (обязателен), «Как найти». Если задан ключ 2ГИС — «Точка на карте»: поиск по адресу или нажатие на карту.
4. Блок «Запись»: «Как записываться» — «Свободно» (сразу участник) или «По заявке» (вы решаете, кого принять); «Уровень», «Сколько мест», «Что взять с собой», «Требования».
5. «Опубликовать». Открывается страница созданного мероприятия: название, время, место, блок «Вы организатор этого мероприятия» с кнопками «Заявки и участники», «Изменить», «Отменить мероприятие». Мероприятие появляется в «Мои мероприятия» (меню аватара).
6. Войти как Мария → «Мероприятия», в поиске ввести часть названия → карточка в ленте → открыть: организатор «Алексей Петров», блок «Записаться».

**Новое направление.** В поле «Направление» ввести название, которого нет в каталоге (например, «Падел»), выбрать пункт «+ Добавить «Падел»». Под полем появится «✦ Новое направление». После публикации оно отображается в карточке и доступно в фильтре «Направление».

**Ошибки и состояния.** Обязательные поля отмечены `*`. Пустые обязательные поля, прошедшее время, окончание раньше начала, число мест вне 1–1000 подсвечиваются текстом под полем, фокус переходит на первое ошибочное поле (`src/utils/eventForm.ts`). Во время отправки кнопка показывает «Подождите…» и заблокирована; ошибка сервера выводится над кнопками. Администратор на `/events/new` перенаправляется в админку.

**Где в коде:** `src/views/EventFormView.vue`, `src/utils/eventForm.ts`, `src/components/ui/UiCombobox.vue`, `src/components/map/LocationPicker.vue`. **Автотест:** `e2e/scenarios.spec.ts`, «С1».
**Ограничения:** без `VITE_2GIS_KEY` точку на карте выбрать нельзя — мероприятие сохраняется без координат и не появится на карте. Создание повторного мероприятия — кнопка «Повторить» в архиве «Мои мероприятия» (форма заполняется данными прошлого).

### Сценарий 2. Допуск организации и публикация мероприятия

**Цель:** организация проходит модерацию и публикует мероприятие от своего имени.
**Роли:** Елена Козлова — представитель; Администратор; Алексей Петров — посетитель; Дмитрий Соколов — представитель уже допущенной организации.
**Начальные условия (чистая база):** у Елены «Шахматный кружок «Гамбит»» — на рассмотрении, «Беговой клуб «Ультра»» — отклонён с причиной.

**Подача заявки.** Любой пользователь: меню аватара → «Моя организация» (`/organizations/my`) → «Подать заявку» (если организаций нет) или «+ Ещё одна». Форма: название, тип (клуб / сообщество / федерация / компания), направления, город, контакты для участников, «О вас», сайт, отдельная галочка согласия на обработку персональных данных. После отправки — «Заявка отправлена. Ответ появится здесь», статус «На рассмотрении».

**Ветка «одобрение»:**

1. Войти как Елена → «Моя организация»: у «Гамбита» статус «На рассмотрении», кнопки публикации нет.
2. Войти как Алексей → `/organizations/2`: «Страница не найдена — организации нет или она ещё не прошла проверку».
3. Войти как Администратор → «Админка» → «Организации». Фильтр «Ждут решения», в таблице «Гамбит» → открыть: владелец, контакты, дата подачи → «Допустить». Статус меняется на «Допущена».
4. Войти как Елена → «Моя организация»: «Гамбит» — «Допущена», появились «+ Мероприятие от организации» и «Страница организации».
5. «+ Мероприятие от организации» → в форме блок «От чьего имени» с выбранной организацией → заполнить и «Опубликовать». Организатор на странице мероприятия — «Шахматный кружок «Гамбит»» с пометкой «организация».
6. Войти как Алексей (или выйти) → «Организации» → «Гамбит»: страница организации с её мероприятием.

**Ветка «отказ»:**

1. Войти как Администратор → «Админка» → «Организации» → открыть организацию на рассмотрении → «Отклонить» → в окне обязательная «Причина» → «Отклонить».
2. Войти как владелец → «Моя организация»: статус «Отклонена», текст «Причина: …» и кнопка «Исправить и отправить снова» (повторная подача переводит заявку обратно в «На рассмотрении»). Публиковать от имени отклонённой организации нельзя — её нет в «От чьего имени».

Готовая ветка для просмотра: «Беговой клуб «Ультра»» у Елены на чистой базе уже отклонён с причиной.

**Ограничения:** уведомлений в интерфейсе нет — результат модерации владелец видит только на «Моей организации» (backend их создаёт, см. [ограничения](#известные-ограничения-и-расхождения)).

### Сценарий 3. Свободное присоединение к мероприятию

**Цель:** пользователь записывается на мероприятие со свободной записью и сразу становится участником.
**Роли:** Мария Иванова — участник; Алексей Петров — организатор. **Начальные условия:** мероприятие 12 «Баскетбол 3×3 на набережной» (свободная запись, 12 мест).

1. Войти как Мария → «Мероприятия» → «Фильтры» → «Запись: Свободная запись» → «Показать N». Карточки показывают время, вид спорта, место и «ещё N мест».
2. Открыть «Баскетбол 3×3 на набережной»: время, место (у вошедшего — точный адрес и карта, если задан ключ 2ГИС), уровень, требования, инвентарь, участники.
3. «Записаться» → сообщение «Вы записаны.», статус «Вы участник», текст «Ждём вас: …» и кнопка «Отменить запись». Появляется «В календарь» (файл `.ics`).
4. Меню «Мои записи» (`/me`), вкладка «Предстоящие» — мероприятие со статусом «Вы участник».
5. Войти как Алексей → страница мероприятия → «Заявки и участники» → вкладка «Участники»: Мария Иванова с почтой.

**Альтернативные ветки.** Мест нет — вместо кнопки «Мест больше нет.»; если backend поставил в лист ожидания — статус «В листе ожидания». Организатор на своём мероприятии видит «Вы организатор этого мероприятия», администратор — «Администратор не записывается на мероприятия», гость — «Войти и записаться». Прошедшее — «Мероприятие уже прошло.». «Отменить запись» спрашивает подтверждение («Отменить запись?» / «Не отменять» / «Да, отменить»), после отмены можно записаться снова. Повторного нажатия нет: после записи кнопка «Записаться» заменяется статусом.

**Где в коде:** `src/components/events/EventJoinPanel.vue`, логика выбора состояния — `src/features/events/participation.ts`, `src/views/MyParticipationsView.vue`, `src/views/EventManageView.vue`. **Автотест:** `e2e/scenarios.spec.ts`, «С3»; `e2e/mobile.spec.ts` (то же на телефоне).

### Сценарий 4. Участие по заявке

**Начальные условия (чистая база):** заявка Алексея на «Товарищеский матч по футболу» (мероприятие 2, ФК «Дворовые легенды», Дмитрий) и заявка Марии на «Настольный теннис на Татышеве» (мероприятие 7, Алексей) — обе ждут решения.

**Подача заявки** (на любом мероприятии «По заявке», например 5 «Ночное ориентирование в лесу»): войти как Алексей → открыть мероприятие → «Подать заявку» → окно «Заявка на участие» с необязательным «Сообщение организатору» → «Отправить заявку». Статус «Ждёт решения», текст «Организатор рассмотрит заявку. Решение появится здесь и в «Моих записях»», кнопка «Отозвать заявку». В «Мои записи» — вкладка «Ждут решения».

**Ветка «принятие»:**

1. Войти как Дмитрий → мероприятие 2 → «Заявки и участники» (`/events/2/manage`) → вкладка «Заявки»: карточка Алексея Петрова с датой и сообщением.
2. «Принять» → заявка уходит из списка, Алексей появляется во вкладке «Участники».
3. Войти как Алексей → мероприятие 2: статус «Вы участник»; в «Мои записи» — вкладка «Предстоящие».

**Ветка «отклонение»:**

1. Войти как Алексей → мероприятие 7 → «Заявки и участники» → заявка Марии Ивановой → «Отклонить».
2. Окно «Отклонить заявку: Мария Иванова»: готовые причины («Группа уже собрана», «Не подходит уровень», «Другое время») и «Комментарий» — всё необязательно → «Отклонить». Заявка переходит во вкладку «Отказы».
3. Войти как Мария → мероприятие 7: статус «Заявка отклонена» и «Причина: «…»». В «Мои записи» — вкладка «Отказы».

**Повторные действия.** Повторное решение по уже рассмотренной заявке невозможно — она пропадает из «Заявок». Подача заявки на своё мероприятие недоступна (блок организатора). **Расхождение:** после отказа интерфейс показывает кнопку «Подать заявку снова», но backend повторную заявку на то же мероприятие не принимает и отвечает «Организатор отклонил вашу заявку» — сообщение выводится под кнопкой (см. [ограничения](#известные-ограничения-и-расхождения)).

**Где в коде:** `src/components/events/EventJoinPanel.vue`, `src/views/EventManageView.vue`, `src/features/events/organizer.ts`, `src/features/events/myParticipations.ts`. **Автотест:** `e2e/scenarios.spec.ts`, «С4» (две ветки).

### Сценарий 5. Уточнение условий мероприятия

**Цель:** вопрос участника и ответ организатора видны в одном обсуждении с понятным авторством.
**Роли:** Мария Иванова спрашивает; Алексей Петров — организатор мероприятия 12. Готовый пример переписки — мероприятие 11 (ответ от имени ФК «Дворовые легенды»).

1. Войти как Мария → мероприятие 12 → блок «Обсуждение» внизу страницы. Пустое обсуждение показывает «Вопросов пока нет. Спросите о том, что важно перед записью».
2. Ввести вопрос в поле «Задать вопрос организатору…» → кнопка «↑» («Отправить сообщение»). Сообщение появляется сразу с именем автора, временем и пометкой «· вы».
3. Войти как Алексей → мероприятие 12 → у вопроса «Ответить» → над полем «Ответ для Мария Иванова», поле «Ответьте участникам или добавьте уточнение…» → отправить.
4. Ответ показывается под вопросом с отступом, с именем «Алексей Петров», меткой «Организатор» и выделенным фоном. Мария видит его в том же обсуждении после открытия страницы.

**Варианты и ошибки.** Владелец допущенной организации отвечает от её имени — под полем подпись «Сообщение будет от имени организации», автором показывается организация. Свои сообщения можно «Изменить» (появляется «· изменено») и «Удалить». Пустое сообщение — «Напишите сообщение.», ошибка сети — «Не получилось отправить. Попробуйте ещё раз.». Гость видит обсуждение и ссылку «Войдите, чтобы задать вопрос.». На снятом мероприятии — «Обсуждение закрыто: мероприятие снято с публикации.». Скрытое модератором сообщение — «Сообщение скрыто модератором» с причиной.

**Где в коде:** `src/components/comments/EventComments.vue`, `src/components/comments/CommentItem.vue`, построение веток — `src/features/comments/thread.ts`. **Автотест:** `e2e/scenarios.spec.ts`, «С5».
**Ограничения:** новые сообщения не приходят в реальном времени — нужно открыть страницу заново; уведомлений об ответе в интерфейсе нет.

### Сценарий 6. Снятие мероприятия с публикации

**Цель:** администратор снимает мероприятие; оно исчезает из выдачи, недоступно по ссылке, участники видят причину.
**Роли:** Администратор; Мария Иванова — участница; Дмитрий Соколов — посторонний. **Начальные условия:** мероприятие 1 «Утренняя пробежка в парке», Мария записана.

1. Войти как Администратор → «Админка» → «Мероприятия» → поиск по названию или фильтр «Опубликованы» → открыть «Утренняя пробежка в парке»: организатор, записи, обсуждение.
2. «Снять» → окно «Снять с публикации?» с обязательной «Причиной» → «Снять». Статус в карточке — «Снято с публикации», причина видна.
3. Войти как Дмитрий (или выйти) → «Мероприятия»: пробежки нет в ленте. Прямая ссылка `/events/1` — «Мероприятие недоступно», «Запись закрыта», ссылка «Найти другие мероприятия»; записаться нельзя.
4. Войти как Мария → «Мои записи»: запись осталась, рядом причина снятия. Страница мероприятия открывается с плашкой «Снято с публикации», причиной и текстом «Записаться на него нельзя. Вы видите страницу, потому что связаны с этим мероприятием», без блока записи и с закрытым обсуждением.
5. Вернуть мероприятие: «Админка» → «Мероприятия» → фильтр «Сняты» → «Вернуть».

**Альтернативные ветки.** «Удалить» — то же окно с причиной, статус «Удалено». В карточке мероприятия админ может «Скрыть» отдельное сообщение обсуждения с причиной. Снятие также происходит при принятии жалобы ([Дополнительные возможности](#дополнительные-возможности)). Правила для существующих записей — как в [backend-README, сценарий 6](https://github.com/crazy-tosser3/StolotoSportBack#сценарий-6-снятие-мероприятия-с-публикации): записи не меняются, участники и организатор продолжают видеть страницу.

**Где в коде:** `src/views/admin/AdminEventsView.vue`, `src/features/admin/events.ts`, недоступное мероприятие — `src/views/EventView.vue`. **Автотест:** `e2e/scenarios.spec.ts`, «С6».
**Ограничения:** уведомления о снятии backend создаёт, но в интерфейсе их нет; участник узнаёт о снятии, только открыв «Мои записи» или страницу мероприятия. Восстановить удалённое мероприятие через интерфейс нельзя (кнопка «Вернуть» есть только у снятых), хотя backend это позволяет.

## Устройство фронтенда

**Что делает.** Одностраничное приложение (SPA) на Vue 3. Показывает данные и отправляет намерения пользователя в REST API backend; бизнес-правила (права, статусы, места, видимость) считает backend, интерфейс отображает его ответ и человеческим языком объясняет отказ.

**Страницы и навигация.** Маршруты — `src/router/index.ts`, страницы — `src/views/` (одна страница — один маршрут, тяжёлые страницы загружаются лениво). На компьютере навигация — шапка с разделами и меню аватара (`src/components/layout/AppHeader.vue`, `AppUserMenu.vue`), на телефоне — нижняя панель с центральной «+» и меню «Все разделы» (`AppTabBar.vue`, `AppMenu.vue`). Состав пунктов для пользователя и администратора — `src/components/layout/nav.ts`.

**Доступ по ролям.** Перед каждым переходом роутер восстанавливает сессию (`session.restore()` → `GET /auth/me`) и проверяет `meta` маршрута (`src/router/access.ts`): `requiresAuth` — на вход с возвратом (`?redirect=`), `adminOnly` — на «Нет доступа», `noAdmin` — администратора в админку, `guestOnly` — вошедшего на главную. Возврат после входа ограничен внутренними адресами (`src/router/redirect.ts`).

**Взаимодействие с backend.** Слой `src/api/`: `http.ts` (fetch, cookie того же домена, разбор ошибок `{error: {code, message, fields}}` в `ApiError`, русские тексты на случай пустого ответа) и модули по ресурсам (`events.ts`, `admin.ts`, `users.ts`, …). Типы генерируются из контракта `openapi/backend.json` в `src/api/schema.d.ts` и уточняются в `src/api/types.ts`: в OpenAPI все поля необязательны, а backend присылает их всегда. Вход — cookie `jwt` (HttpOnly), её ставит backend; фронтенд токен не видит и не хранит.

**Состояние и загрузка данных.** Глобально хранится только сессия: текущий пользователь и его организации (`src/stores/session.ts`, Pinia). Остальное — локальное состояние страниц: каждая загружает свои данные и держит явное состояние `loading` / `ready` / `error`. Фильтры, вид ленты, сортировка и выбранная запись в админке живут в адресе страницы, поэтому ссылкой можно поделиться. Повторяющаяся логика — в composables и чистых функциях `src/features/` (покрыты тестами).

**Формы и обработчики.** Формы — в страницах и `src/components/` (`OrgForm.vue`, `EventReport.vue`, окна `UiModal`); правила валидации — чистые функции рядом (`src/utils/eventForm.ts`, `src/features/*/…Form.ts`, `features/reports/reports.ts`). Ошибки полей от backend (`fields`) подставляются к соответствующим полям.

## Дизайн-система

Источник истины — токены в `src/assets/main.css` (блок `@theme`) и компоненты `src/components/ui/`. Живой образец всех компонентов и состояний — страница `/ui-kit` (`src/views/UiKitView.vue`).

- **Цвета** (`--color-*`): `ink` / `ink-2` — основной и вторичный текст, `page` — фон страницы, `card` — поверхности, `field` — поля и вторичные кнопки, `mute` — линии, бренд — `accent` (барвинок), `accent-soft`, `lilac`, `orange` (акцент «Создать»), `accent-strong` — фокус. Статусы — парами фона и текста (`success-*`, `warning-*`, `queue-*`, `danger-*`), одинаковыми в обеих темах; статусы различаются ещё и значком (✓ ◷ ✕), а не только цветом (`src/components/ui/status.ts`).
- **Тёмная тема** — те же токены с другими значениями (`:root[data-theme='dark']` и `prefers-color-scheme`), выбор в шапке, хранится в браузере (`src/features/theme/theme.ts`).
- **Типографика:** Exo 2 Black Italic — заголовки и логотип, Inter Tight — интерфейс и текст, Caveat — короткие рукописные пометки. Базовый размер шрифта — 16 px. Шрифты подключены из бандла.
- **Скругления и тени:** `--radius-*` (карточки 26 px, поля 16 px), `--shadow-raised`, `--shadow-header`. Отступы — шкала Tailwind; карточки и секции — `p-4`/`p-5`, промежутки `gap-3`…`gap-5`.
- **Кнопки и поля:** `UiButton` (основная, акцентная, вторичная; состояние загрузки «Подождите…» и блокировка), `UiTextField`, `UiTextArea`, `UiSelect`, `UiCombobox` (с добавлением своего варианта), `UiCheckbox`, `UiChip`. У полей — подпись, подсказка, ошибка с `aria-invalid` и `aria-describedby`.
- **Карточки:** `EventListCard.vue` — цветная обложка по виду спорта, дата, название, место, уровень, места; `UiCard` — общая поверхность.
- **Состояния:** hover — затемнение или фон `mute`; focus — видимая обводка `accent-ink` / `accent-strong` (`:focus-visible` в `main.css`); disabled — пониженная непрозрачность; loading — скелетоны `animate-pulse` и «Подождите…»; error — блок с текстом и «Повторить».
- **Анимации** отключаются при «уменьшить движение» в системе (`prefers-reduced-motion` в `main.css`), сторис открываются на паузе.
