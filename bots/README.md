# Боты-симуляторы пользователей

`simulate.py` запускает пачку ботов, которые параллельно ходят в API так, как это делали бы живые люди. Нужен только Python 3.9+, зависимостей нет.

## Персоны

| Персона | Что делает |
|---|---|
| `guest` | Без входа: листает ленту, фильтрует по спорту, городу, уровню и датам, открывает карточки, читает комментарии, смотрит виды спорта, организации и профили |
| `participant` | Регистрируется, заполняет профиль, записывается на события и иногда отменяет запись, пишет, правит и удаляет комментарии, читает уведомления и свои записи |
| `organizer` | Регистрируется, создаёт события (`open` или `approval`), одобряет или отклоняет заявки, отвечает в обсуждениях, правит события, изредка отменяет их |

Боты-организаторы стартуют первыми, а их события сразу становятся видны участникам. Поэтому ботам есть с кем взаимодействовать даже на пустой базе.

## Запуск

```bash
python3 bots/simulate.py --base-url http://localhost:8080 --bots 20 --duration 120
```

```bash
python3 bots/simulate.py --mix guest=10,participant=20,organizer=3 --duration 300 --think 0.5 2 --cleanup -v
```

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--base-url` | `http://localhost:8080` | Адрес приложения без `/api/v1` |
| `--bots` | 10 | Сколько ботов запустить. Делятся так: ~10% организаторов, 50% участников, остальные гости |
| `--mix` | — | Точный состав, например `guest=5,participant=10,organizer=2` |
| `--duration` | 60 | Сколько секунд работать; `0` — до Ctrl+C |
| `--think MIN MAX` | `1 4` | Пауза между действиями бота в секундах |
| `--ramp-up` | 10 | За сколько секунд запустить всех ботов |
| `--no-fake-ips` | — | Не подставлять `X-Forwarded-For` (подробности ниже) |
| `--cleanup` | — | Удалить аккаунты ботов в конце через `DELETE /users/me` |
| `--seed` | — | Seed для воспроизводимого поведения |
| `-v` | — | Писать в лог каждое действие ботов |

Каждые 5 секунд выводится прогресс. В конце печатается таблица по каждому эндпоинту (количество запросов, p50/p95/max, коды ответов) и сводка действий ботов. Если были ответы 5xx или сетевые ошибки, скрипт завершается с кодом 1, так что его можно ставить в CI.

## Особенности

- **Авторизация.** JWT приходит в cookie `jwt` с флагом `Secure`, а по `http://` такую cookie клиент не отправит. Поэтому бот достаёт токен из `Set-Cookie` и передаёт его в `Authorization: Bearer`.
- **Rate limit.** `RateLimitFilter` считает лимиты по IP: на `register` и `login` — 10 запросов в минуту. Без подмены IP уже 11-й бот не смог бы зарегистрироваться. Поэтому каждый бот по умолчанию отправляет свой `X-Forwarded-For`. Чтобы проверить сам лимит, запустите с `--no-fake-ips`. Если сервер всё же ответил 429, бот ждёт `Retry-After` и повторяет запрос.
- **Учётные записи.** Боты регистрируются как `bot-<run_id>-<персона>-<n>@bots.test`. `--cleanup` удаляет только аккаунты, а созданные ботами события, заявки и комментарии остаются в базе. Поэтому гоняйте ботов на тестовой базе, а не на проде.
